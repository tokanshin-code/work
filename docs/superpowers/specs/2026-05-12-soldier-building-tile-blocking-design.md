# Soldier Building Tile Blocking Design

## Goal

Use the lightweight recommended rule set so soldiers spawn on adjacent non-building tiles and treat live building tiles as blocked until the building is destroyed.

## Current Context

- Main logic lives in `src/game/HexGameController.ts`.
- Buildings already store `tileCol` and `tileRow` in `SpawnBuilding`.
- `spawnUnit()` currently receives a building position and offsets the unit toward the enemy base, so units can visually originate from a building tile.
- `updateUnits()` moves units directly toward the opponent base when there is no target in range, so units can step into live building tiles.
- Destroyed buildings are removed in `removeDestroyedBuildings()`, which also refreshes walls and unlock labels.

## Rules

1. A live building tile is blocked for unit standing and movement.
2. A unit generated by a unit building should spawn on an adjacent standable tile, not the building tile.
3. A standable spawn tile is any adjacent tile that is not water, not void, and does not contain a live building.
4. When a unit wants to attack a building, it should move to a nearby standable adjacent tile and attack from there.
5. Units cannot enter a live building tile. After that building is destroyed and removed from the building list, the tile becomes standable again.
6. If no adjacent standable tile exists, keep the current directional offset fallback so unit production does not stall completely.

## Approach

Use a small set of helper methods inside `HexGameController` rather than introducing full hex pathfinding.

- `isStandableUnitTile(tile)` returns false for water, void, and live-building tiles.
- `findUnitSpawnTile(building, team)` chooses the best standable neighbor around the source building, preferring the neighbor closest to the opponent base.
- `findApproachTileForBuilding(unit, building)` chooses a standable neighbor around a target building, preferring the neighbor closest to the unit.
- `getUnitMoveTarget(unit)` returns an approach tile for the nearest live enemy building when needed; otherwise it keeps the current enemy-base fallback.
- `moveToward()` continues to move in world space, but callers pass target positions that are never live building centers.

## Testing

Add a source-level regression test in `.temp/soldier-building-tile-blocking-source.test.mjs` because this project already uses `.temp/*.test.mjs` source checks for gameplay invariants.

The test should verify the source contains helpers and wiring for:

- Spawn selection from adjacent standable tiles.
- Live building tile blocking.
- Building approach tile selection.
- Destroyed building tiles becoming passable by relying on live-building checks.
- Fallback behavior when no standable neighbor exists.

## Scope

This change intentionally avoids full pathfinding. It only enforces building tile occupancy and adjacent attack staging, which matches the requested optimization and keeps the playable-ad behavior simple.
